# ADR-008: Immutable observations and case annotations

- Status: Accepted
- Date: 2026-09-17

## Context

Analysts need to mark an event benign or relevant without changing what the source originally reported.

## Decision

Treat persisted canonical events as immutable after ingestion. Store relevance, notes and finding associations on the case evidence layer. Do not expose event edit/delete endpoints. ORM hooks reject source-event updates and deletes. Alembic migrations install PostgreSQL and SQLite triggers rejecting ordinary UPDATE/DELETE for both canonical events and audit records. Source Pydantic models are top-level frozen; nested in-memory dictionaries are not recursively immutable.

## Consequences

Source observations stay stable across analysis and reports. Trigger enforcement requires migrated tables. The trusted CLI reset deliberately downgrades and reapplies migrations, dropping and recreating the demo records and triggers. A database owner can remove protections or change schema, so these controls do not establish privileged-owner resistance or cryptographic evidence integrity. Production needs restricted roles and independent retained copies.

## Alternatives considered

Editing canonical events in place would erase provenance and make prior model and analyst results difficult to explain.
