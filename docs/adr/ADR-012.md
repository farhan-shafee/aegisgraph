# ADR-012: Typed rule revisions and corpus regression before human approval

- Status: Accepted
- Date: 2026-09-21

## Context

A threshold change can remove a useful signal or affect other rules. In particular,
the authentication novelty baseline also affects later MFA and privilege-sequence
rules. A raw rule editor and a comparison of only the edited rule would conceal
these dependencies. Historical Atlas evidence must remain reproducible.

## Decision

Represent revisions as immutable, validated snapshots. Expose only parameters that
the detector actually uses, with strict integer ranges and fixed rule identities
and kinds. There is no expression language or executable rule upload. Parameter
descriptions use the effective values rather than retaining stale baseline text.

Compare the complete current and proposed rulesets over the independently labeled
scenario corpus. Preserve baseline expected firings separately from mandatory
regression obligations: an expected alert on approved administration or benign
automation is not automatically coverage that must be retained.

Use explainable gates rather than a composite score:

- **BLOCK:** a required signal is lost, a forbidden signal appears, or a labeled
  correlation invariant fails.
- **WARN:** the change has no demonstrated fixture improvement or increases
  permitted alert burden on benign fixtures.
- **PASS:** the measured fixture change improves behavior without violating the
  blocking policy.

Every result identifies the corpus, baseline and proposed ruleset digests, changed
parameters, observed per-scenario differences and individual reasons. Counts are
synthetic fixture measurements with explicit denominators; they are not real-world
precision, recall, model accuracy or security guarantees.

Local proposals, regression runs and human decisions are separate records. Approval
recomputes the regression server-side and rejects a stale whole-ruleset baseline.
A transactional generation check prevents concurrent approvals from bypassing that
comparison, including changes to different rules. The fixed analyst label is an
unauthenticated local attribution label, not an authenticated identity.

Approved revisions affect subsequent local replay and comparison. They never rewrite
canonical events, stored Atlas alerts, case IDs or historical evidence. Public
visitors inspect the shipped rules and predefined comparisons; public GET requests
must not lazily initialize workflow rows. Existing method-level write denial stays
authoritative.

## Consequences

The corpus can demonstrate a specific tradeoff: reducing a volume alert on labeled
reconciliation activity while retaining required service-principal and Atlas
signals. Passing that comparison says nothing about unmodeled traffic. Expanding
the rule language, corpus or gate policy requires explicit review and tests.

Relational storage and additive migrations fit the existing system. No arbitrary
code editor, message broker, learned risk score or automatic rule deployment is
introduced. Database immutability controls exclude a privileged owner who can
remove triggers or rewrite storage.
