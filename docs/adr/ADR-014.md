# ADR-014: Bounded JSON evidence bundles and local hash verification

Status: accepted

## Context

An interviewer should be able to inspect an exported investigation and detect
changes to its files. Public reads must not mutate PostgreSQL or require additional
storage, a signing service, uploaded archives, or a new trusted execution boundary.

## Decision

Export one bounded JSON container with a manifest, fixed logical filenames, exact
UTF-8 contents, and SHA-256 file digests. Take a consistent read-only snapshot and
reject over-capacity cases instead of truncating them. Distinguish the public
synthetic projection from the local analyst projection. Verification runs locally;
logical filenames are never extracted or opened as paths.

Capture the actual generation timestamp once. The same snapshot and timestamp
produce the same serialized files and hashes. The manifest itself is unsigned and
replaceable, so verification establishes consistency with the supplied manifest,
not authenticity or source truth.

## Consequences

No export table, object store, ZIP parser, signing key, or public upload route is
needed. Existing JSON proxy and centralized public write denial remain sufficient.
The 2 MiB format intentionally fits the synthetic fixture, not an unlimited evidence
archive. A future authenticity requirement would need separately designed signing,
trusted key distribution, source provenance, and retention controls.

See [the format and limitations](../EVIDENCE_BUNDLES.md).
