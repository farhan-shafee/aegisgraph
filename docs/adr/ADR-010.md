# ADR-010: A code-backed scenario corpus with separate evaluation labels

- Status: Accepted
- Date: 2026-09-20

## Context

One incident cannot demonstrate both detection coverage and false-positive
tradeoffs. Public visitors must be able to inspect varied synthetic activity
without appending anonymous data to the hosted PostgreSQL database. The existing
Atlas fixture is already deployed, and its event, alert and case IDs are useful
stable references.

## Decision

Keep the existing Atlas generator and persisted fixture. Add a finite, versioned
catalog of inert synthetic scenarios in application code. Their generators use
the same canonical schema and adapters as Atlas. Identifiers are scenario scoped;
event order is `(timestamp, event_id)`. Callers receive fresh objects so mutation
of nested attributes cannot poison another request.

Analyst-visible catalog metadata describes the exercise and telemetry size.
Expected detections, forbidden detections, correlation outcomes, claim limits and
question outcomes live in a separate evaluator-only ground-truth module. Those
expectations are authored independently and tested against execution. Scenario
generation does not import the evaluator, and provider context receives only
case-scoped observation projections. Showing benchmark expectations in an
explicit evaluation view is distinct from supplying them to an analyst provider.

Read-only catalog routes select known IDs; they do not accept uploaded telemetry,
generator code, or arbitrary event counts. Pure detection/correlation can run over
these scenarios without changing the canonical database. Persistent local human
workflow is a separate explicit operation, never a side effect of browsing.

## Consequences

The corpus is reviewable and reproducible in CI without external services. It
tests the rules against named synthetic cases, not production traffic. Classification
describes a simulation's design and is not a verified attribution about a person.
Approved activity may still generate legitimate security signals. A new scenario
or changed expectation requires a reviewed source change and corpus version.

This approach deliberately avoids a second scenario database, public seed route,
broker, or arbitrary simulation runner. It does not execute attacks, malware,
network requests, or endpoint commands.
